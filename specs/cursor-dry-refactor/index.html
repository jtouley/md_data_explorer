    Semantic Model Refactor: Eliminate Hardcoded Logic

    Transform the platform from a hybrid config/hardcoded system to a fully semantic, idempotent model where all transformations, filters, aggregations, and defaults are driven by datasets.yaml.

    Current Issues

    1. Loaders have hardcoded transformations that duplicate YAML config
    2. Dataset classes have hardcoded filter logic instead of using mapper
    3. Aggregation logic is hardcoded in sepsis loader, ignoring config
    4. Time zero, outcome selection, and labels are hardcoded in dataset classes
    5. SQL queries are hardcoded in MIMIC3 loader instead of using config
    6. Non-idempotent: Same config can produce different results depending on execution order

    Solution Architecture

    Phase 1: Enhance ColumnMapper with Missing Capabilities

    File: src/clinical_analytics/core/mapper.py

    1. Add filter application engine:

    2. apply_filters(df: pl.DataFrame, filters: dict) -> pl.DataFrame

    3. Support config-defined filter types: equals, in, range, exists

    4. Read filter definitions from default_filters in config

    5. Add aggregation engine:

    6. apply_aggregations(df: pl.DataFrame, group_by: str) -> pl.DataFrame

    7. Read aggregation specs from aggregation section in config

    8. Support methods: first, last, max, min, mean, sum, count

    9. Enhance outcome transformations:

    10. Support aggregation type outcomes (currently only handles binary with mapping)

    11. Apply transformations during map_to_unified_cohort() automatically

    12. Add config-driven defaults:

    13. get_time_zero_value() -> Optional[str] - read from config

    14. get_default_outcome_label(outcome_col: str) -> str - read from config or derive
    15. get_default_filters() -> dict - already exists, ensure it's used

    Phase 2: Refactor COVID-MS Loader

    File: src/clinical_analytics/datasets/covid_ms/loader.py

    1. Remove hardcoded outcome transformations (lines 33-46):

    2. Delete normalize_outcome() function (unused)

    3. Remove hardcoded pl.when().then().otherwise() logic

    4. Keep only raw data loading: load_raw_data() and basic cleaning (null handling)

    5. Apply outcome transformations via mapper:

    6. clean_data() should accept a mapper: ColumnMapper parameter

    7. Call mapper.apply_outcome_transformations(df) instead of hardcoding

    File: src/clinical_analytics/datasets/covid_ms/definition.py

    1. Remove hardcoded filter logic (line 66):

    2. Delete special-case confirmed_only handling

    3. Use mapper.apply_filters(df, all_filters) instead

    4. Remove hardcoded defaults (lines 82-84):

    5. time_zero_value → mapper.get_time_zero_value()

    6. outcome_label → mapper.get_default_outcome_label(outcome_col)

    7. Update load() method:

    8. Pass self.mapper to clean_data() so it can apply transformations

    Phase 3: Refactor Sepsis Loader

    File: src/clinical_analytics/datasets/sepsis/loader.py

    1. Make aggregation config-driven:

    2. load_and_aggregate() should accept mapper: ColumnMapper parameter

    3. Read aggregation specs from mapper.config.get('aggregation', {})
    4. Build Polars aggregation expressions dynamically from config

    5. Support both static_features and outcome aggregation sections

    6. Remove hardcoded column names:

    7. Use config to determine which columns to aggregate and how

    8. Patient ID extraction should come from config if possible

    File: src/clinical_analytics/datasets/sepsis/definition.py

    1. Remove hardcoded defaults (lines 79-81):

    2. time_zero_value → mapper.get_time_zero_value()

    3. outcome_col → mapper.get_default_outcome()

    4. outcome_label → mapper.get_default_outcome_label(outcome_col)

    5. Update load() method:

    6. Pass self.mapper to load_and_aggregate() for config-driven aggregation

    7. Use mapper for filters:

    8. Replace simple filter loop with mapper.apply_filters(df, filters)

    Phase 4: Refactor MIMIC3 Loader

    File: src/clinical_analytics/datasets/mimic3/loader.py

    1. Remove hardcoded SQL query (lines 84-113):

    2. Delete _get_default_cohort_query() method

    3. Always use query from config (already partially done in load())

    4. Ensure config is single source of truth:

    5. load_cohort() should require query parameter or read from config

    6. No fallback to hardcoded query

    File: src/clinical_analytics/datasets/mimic3/definition.py

    1. Remove hardcoded outcome_label (line 114):

    2. Use mapper.get_default_outcome_label(outcome_col) instead

    3. Use mapper for filters:

    4. Replace simple filter loop with mapper.apply_filters(df, filters)

    Phase 5: Update Config Files

    File: data/configs/datasets.yaml

    1. Add missing config sections:

    2. time_zero section with value or source_column for each dataset

    3. filters section with filter definitions (type, column, default_value)

    4. Ensure aggregation section is complete for sepsis

    5. Fix duplicate keys (line 26):

    6. outcome_hospitalized: outcome_label is duplicate - should be separate config

    7. Add outcome_label mappings:

    8. Define default outcome labels for each outcome type

    Phase 6: Update Tests

    Files: tests/test_mapper.py, tests/test_covid_ms_dataset.py

    1. Add tests for new mapper methods:

    2. test_apply_filters()

    3. test_apply_aggregations()
    4. test_get_time_zero_value()

    5. test_get_default_outcome_label()

    6. Update existing tests:

    7. Ensure tests still pass after refactoring

    8. Add tests for idempotency (same config = same result)

    Implementation Order

    1. Phase 1 (Mapper enhancements) - Foundation for everything else
    2. Phase 5 (Config updates) - Ensure config has all needed fields
    3. Phase 2 (COVID-MS) - Simplest dataset, good starting point
    4. Phase 3 (Sepsis) - More complex with aggregation
    5. Phase 4 (MIMIC3) - SQL-based, different pattern
    6. Phase 6 (Tests) - Validate idempotency and correctness

    Success Criteria

    • ✅ No hardcoded transformations in loaders
    • ✅ No hardcoded filter logic in dataset classes
    • ✅ All defaults come from config
    • ✅ Same config always produces same result (idempotent)
    • ✅ Adding new dataset requires only YAML config (zero code changes)
    • ✅ All existing tests pass
    • ✅ New tests verify semantic model behavior
