    ADR014: Aggregate-data mode (population estimates)

    Status

    Proposed (2026-11-14); revised 2026-11-19 with joins across tables (§10) and a hardened declaration (§7). Branch feat/aggregate-mode carries the population corpus commits of feat/acceptance-corpus-multi and the paused wip/paused-agg work, reviewed and extended.

    Note 2026-11-20 (ADR015): the app no longer hides small counts on screen for any data, so §7 is no longer an exception to an app-wide small-cell rule. Its "trust the source" handling is unchanged: declared estimates are shown as published, and cells the source suppressed stay hidden and are never turned into numbers.

    Why its own ADR, not a section of ADR013. ADR013 designs one path, governed SQL. This mode changes what a row is (an estimate for a group, not a patient), and that change governs both paths: the intent path today and the SQL gate later. It also records an approved privacy decision that relaxes two rules for declared datasets. A decision of that weight needs its own record that ADR013 can point to, instead of being buried in §5.2.

    Problem

    CDC tables of causes of death, rates and indicators, CMS hospital C. diff ratios, WHO TB and GBD extracts hold rows that are estimates. Each row has key dimensions (location, year, age, sex, cause, measure) and a value, often with lower and upper bounds. On main, a real IHME file gave:

    • Pooled overlapping categories. "Average mx by cause" averaged Male, Female and Both, a state and its own counties, and all years, without weights, labelled as n patients: 291 where the right figure is about 204–210.
    • A patient test on estimates. An ANOVA across Male, Female and Both, p<0.001.
    • Patient limits on public data. At most 20 groups and the small-cell rule blocked a trend by year and any question about counties.
    • Packed Excel cells. IHME's Excel tables hold "401.63 (390.33, 412.62)" in one text cell and put years in columns.

    Decision

    1. Detecting the key dimensions and the value columns (core/estimates.py)

    detect_estimate_table(view, rows) runs once per layer state. Each count is a DuckDB aggregate.

    • Bounds. A numeric column x with x_lo/x_hi, x_lower/x_upper or another configured suffix pair (WHO). Also standalone lower/upper or lowconfidencelimit/highconfidencelimit beside exactly one val, mx, best, datavalue and the like (GBD, IHME, CDC CDI). Configured in contracts/config.py (ESTIMATE_*).
    • Candidate keys. Text columns and integer columns named for a key (year, *_id, FIPS, ISO). Other numeric columns are values; a value is a rate, a count or another value, by name.
    • Key. The candidates must key every row exactly (COUNT(DISTINCT key) = rows, the expect_compound_columns_to_be_unique check).
    • A column that repeats another row for row is an alias (sex_id beside sex, FIPS beside location_name).
    • A column the others determine is an attribute, not a key (g_whoregion beside country). The most varied columns are dropped first, so an ID added at upload never displaces a real key.
    • Not estimates. A key column with more than rows/2 levels (a record ID), except a state column (at most 51 levels: one row per state is an aggregate table); or no interval, rate, total level or place key (states, counties, local jurisdictions) anywhere. Patient-level files fall out here; the corpus check found no false positive among the patient sets. Columns the app adds to the view (time_zero, outcome_label) are skipped.
    • Never patient data. A table whose key includes its own patient ID (visits, repeated measures) is never an estimate table, whatever its column names say. A bare number is read as a FIPS code only in a column named for a place (FIPS, state, county, location), so patient numbers 1–56 or a week column are never states. Detection alone never changes how a table is counted: the patient key is dropped, and counts say "rows", only for a declared table.
    • Totals (parents). A level is the total of the others in its column when:
    • it is named as one ("Both", "All Sexes", "All ages", "United States", "Overall", "Entire Network", WHO "a" beside "m"/"f");
    • it is an age band containing another band present ("65+" beside "65-74"), only in a column named for age;
    • it is a non-county level in a column where the other levels are counties (the state row beside its counties).

    The single total of all other levels, when there is one, is the column's top.

    Detection only adds checks. It never relaxes a rule (see 7).

    2. Totals are parents, never peers

    • Grouping by a dimension. Its total levels are left out of the groups, and the answer says so: "Both is the total of the other sex values, so it is left out."
    • Counties. "Which Colorado county …" ranks the counties, not the state row.
    • A dimension the question leaves open. It is never averaged across (see 3).

    3. Holding a question when a dimension isn't fixed (check_plan)

    After the plan's limits, each key dimension that is not grouped must have one level left.

    • Grounding first. ground_plan reads only the question's words and the published levels. Years: one pins, several with "from/between/change" become groups, "by year"/"trend" groups. Level phrases: plural-insensitive, longest match ("cardiovascular disease" names "Cardiovascular diseases"). The question's exact value-column name wins over a fuzzy parse.
    • Hold. If every open dimension has a top, the question is held: "The question doesn't fix sex (Both, Female, Male; Both is the total). Confirm to use sex = Both and save that choice for this dataset, or name another value."
    • Confirming saves the choice. It is stored as DimensionChoice in declarations.json (per dataset version), which is the contract's declarations section (ADR013 §1.2 source 4). It is an approved plan change: later answers use it and say "Uses sex = Both, the choice saved for this dataset."
    • Refusal. If any open dimension has no total (year, cause), the question is refused and the refusal names what to fix. No confirmation can release it.
    • Word accounting. Forward accounting still runs on the words left after the estimate vocabulary (ESTIMATE_QUESTION_WORDS). Reverse accounting is replaced by the answer naming every level it is for ("mx for location_name = Colorado, cause_name = …, sex = Both, year_id = 2014").

    4. Never pooling rates without weights

    • A mean, median or sum across estimate rows is never computed. A question whose limits leave more than one row per group is held or refused (3).
    • Grouping by an attribute (WHO region) is refused: "g_whoregion does not identify the estimates, so a breakdown by it would mix several estimates in each group."
    • A share of rows is refused: a share of rows is not a share of people.
    • Later. A weighted pool SUM(rate*w)/SUM(w) with the contract's weightColumn (population), per ADR013 §5.2, once a population column is declared. Not in this PR.

    5. Intervals carried to the answer

    • Value column. It keeps its file name. Every row shows lower and upper, and the claim writes "209.52 (203.89 to 215.40)".
    • Interval check. lower ≤ value ≤ upper is checked per shown row (the GX expect_column_pair_values_a_to_be_greater_than_b pair, or_equal=True). A row that fails, or has one bound missing, shows no interval and is named in a note.
    • Comparing two estimates. "Their intervals don't overlap, so the estimates differ"; or "Their intervals overlap, so these estimates are not shown to differ"; or, without intervals, "can't be judged".
    • Ranking. The top group, and the groups whose intervals overlap it: "its rank among them is uncertain".
    • Trends. First and last points in the claim, all points in the table.

    6. Patient-level tests off

    On an estimate table:

    • COMPARE_GROUPS compares intervals, never ANOVA or a t-test, and says "no significance test is run on them".
    • FIND_PREDICTORS, CORRELATIONS and SURVIVAL are refused.
    • COUNT counts rows and says "rows". No column is a patient key, so an ID synthesized at upload never makes a row a patient.

    7. The declaration flow (approved privacy decision)

    • The mark. At upload, the person ticks "Public population estimates – no patient-level data" (POST /datasets/upload, form field population_estimates). The statement they agree to: "Every row is a published estimate for a place, period or group (for example a rate per 100,000 with its interval), and no row describes a single patient."
    • Hard to set by accident (sharp-edges review):
    • The field is not a boolean. Only the exact value public_population_estimates_no_patient_rows (POPULATION_ESTIMATES_FORM_VALUE) declares it. true, on, 1 or yes (a checkbox default, a script flag) are rejected with 400, never read as yes. Absent or empty means not declared.
    • It is bound to the dataset version stored by that upload. A later upload under the same dataset (an overwrite, which may hold patient rows) is not covered until it is declared again. A declaration without a version covers nothing.
    • It relaxes nothing unless detection agrees (§1). A declared file whose rows don't look like estimates keeps the full patient rules, and the upload response says so (population_estimates_note).
    • Never patient data: an allowlist, fail closed (core/public_shape.py, round 4). The estimates path is open only when the table passes every rule below. Anything else is refused, whatever was declared.
      • What the guard is for (owner's scope, round 6). Its realistic job is catching a patient file declared public by mistake: a lab extract, a visit list, a registry export ticked by the wrong person. It is not built to defeat a file deliberately disguised as public (codenames or nicknames as labels, patients mapped onto place names). That stays the owner-accepted residual risk below, and the exact declaration value is the safeguard.
      • Every column is checked, whatever its type (round 6): the ID-name check runs on all columns. Dates and datetimes are refused when named for a person's own events (birth, dob, visit, admit, admission, discharge, encounter, death) or when they vary in a way no published period key fixes. Booleans are flags. Any other type (lists, durations, structs) fails closed.
      • A place is required (round 5). Every declared table must have a key of recognised places (state, territory, region, county, the nation or countries), or one place for the whole file (a state's own table). A time-only or label-only table is refused: every public source the owner works from has a place.
      • A column named as a person or record ID refuses the table whatever its values (subject_id, patient_id, mrn, MemberNo), key or not. "Patient Days", "Member Months" and "Beneficiary Count" are values, not IDs.
      • Every key column is a recognised public dimension, by its values. Values match whole (exactly, or fully by a pattern), never by prefix. Recognised:
      • places: US states, territories (both "Virgin Islands, U.S." spellings), census regions and divisions, HHS regions ("Region 1"–"Region 10"), counties (FIPS in a geography-named column, or "Name County, ST"), the nation and countries;
      • time: years, months (YYYY-MM), dates, MMWR weeks (202401, or 1–53 in a week-named column) and flu seasons (two consecutive years, "2022-23");
      • standard age bands, sex, and standard race/ethnicity labels;
      • totals ("Total", "All ages", "Both sexes") and placeholders ("Unknown", "Other", "Not stated", an empty level). A placeholder is recognised but never counts as a published total: one blank cell in a patient grid is empty too.
      • a year beside week numbers (FluView, NREVSS: YEAR × WEEK) or month numbers 1–12 is one time dimension; any other second time key (a year beside a visit month) is refused.
      • Label columns (cause, indicator, measure, topic, question...): each other value is alphabetic, with at least two distinct values, and is none of these:
      • a value holding a person or record word (patient, subject, resident, participant, member, client, case, mrn, record, room, bed);
      • a letters-then-digits code ("A12", "MRN.0007"; named public-health codes such as COVID-19 and H1N1 excepted; ICD codes only in an ICD-named column);
      • a person's name in any script and case (Unicode letters, particles such as de, la, van, bin, al-, titles such as Dr, Mrs, Prof), "Last, First", or a surname with an initial. Three in ten names make a column of names; one odd title-case label ("Selected Hospitals") does not. Binomial Latin names ("Shigella sonnei") are not people;
      • a word beside a long number ("Admission 004417") or digits-dash-letters ("12345-ABC");
      • a value mixing Latin with lookalike letters of another script. Values are NFKC-normalised first (fullwidth "ＭＲＮ０００７" reads as "MRN0007"), with zero-width characters removed. Published ICD ranges after a cause ("Tuberculosis (A16-A19)") and serogroups ("O157:H7") are part of the label. A place among labels ("Texas" in a cause column) never satisfies the place requirement.
      • Clinician and name columns. A column named for a provider, physician, doctor, clinician, nurse, attending or surgeon refuses the table when any value reads as a name, titled ("Dr. Patel", "Mrs Jones") or with a particle ("Del Rio, Ana", "Le Van Anh"). Any other attribute is refused when ESTIMATE_NAME_SHARE_LIMIT (three in ten) of its values read as names. A text column with more distinct values than can be listed is scanned on a fixed sample of that size, never skipped.
      • A person's own dates are never a time key: birth_year × birth_month, visit_month, and the same stems inside a name ("birthyear", "dobyear", "admityear", "yob", "dod"). A value column such as "Deaths" is unaffected: only time keys and dates are refused on these names.
      • ICD lists after a cause are stripped only in a cause or ICD column and only after a cause that reads as one ("#Assault (homicide) (U01-U02,X85-Y09,Y87.1)" passes; "Smith (B12)" does not). A code starting with a letter of any script ("É12") is a code. A table with a label key must also have a place or time key and an estimate: a value with an interval, a rate value or metric, or a published total level.
      • Demographics only (sex × age band × race, no place or time key) needs an interval or a total level: a rate beside categories alone is refused.
      • At most one time-only key (a year beside a visit month is a person's visits).
      • Every other column is scanned too (attributes and aliases, no lower level threshold): person-named columns, a name column ("name", "full_name") unless every value is a place (Census NAME), SSN, MRN, case-number and contact shapes, mixed-script values, a third of values reading as person names, and half the values ID-shaped. A code column is exempt from the ID-shape rule only when it is an alias of a key, holds one value, or is fixed by one key column (GBD location_id, CDC stratificationid1); a per-row MRN is none of these.
      • One row per state, territory or region is an aggregate table, not a record list.
      • Messages never list key values of a refused table; the log names only the rule.
    • Staging order. A declared upload is first staged exactly as an undeclared one (the source's markers such as "<5" stay text). Detection and the guard run on that, with any column the markers alone would make numeric read as those numbers, unflagged. Only when the guard accepts it, and the table staged with the markers is accepted too, is the public staging kept. A declared but refused file is therefore byte-for-byte the undeclared staging: a lab file's "<5" stays text and statistics of it are refused as before. The same order applies to each declared CSV inside a ZIP, and must cover every reader added later (.tsv/.txt, WONDER files).
    • Fail closed: a patient file is never reinterpreted. A source's markers, the words ("Suppressed", "12.3 (Unreliable)", "Not Applicable") as well as "<10", "(D)" and "*", are read as suppression only in a table declared public and accepted by the guard, or in a file in CDC WONDER's own layout (first column "Notes"). Any other file is staged exactly as before this ADR: in a patient file "<5" or "Suppressed" is the text it says, and a column holding it stays text. Reading a patient's "Suppressed" as a withheld number would change the data the user uploaded without their saying so. The same rule applies to every reader: CSV, .tsv/.txt, Excel, numbered file sets and each table of a ZIP, and a declared ZIP passes its declaration to each of its tables.

    • Residual risk (stated, not solved). A deliberately declared patient file shaped exactly like a public table (place × year × age band × sex rows of rates) cannot be told apart, so the exact declaration value is the safeguard there. The same holds for patients mapped onto place names × time: a patient file keyed by state or county names used as IDs, beside a month. The tests pin both as accepted when declared, so a change in this behaviour is seen.

      A refused table is answered under the patient rules. On the chat path, a dataset with a real patient key is never an estimate table either. A declared estimate table gets numbered rows (row_number, counted as rows), never a patient_id. - Never mixed. The aggregate route refuses any table not declared for its current version, before reading or naming its levels, so a declared public table never joins or sits beside a patient-level upload. - Where it is stored. - Per dataset version in declarations.json (PopulationEstimatesDeclaration.dataset_version). - In the contract's customProperties (privacyClass: public_aggregate, populationEstimates). - Echoed in the upload response. - Declared estimate tables: trust the source. Owner's decision, 2026-11-19. This replaces the earlier rule that counts in declared tables keep the 1–10 rule. - A declared public table (GBD, CDC WONDER, AtlasPlus and similar) is shown as published: rates, percents, intervals and counts, GBD "Number" rows included. The publisher has already applied its own disclosure rules, and re-hiding its published numbers would make the app disagree with the source the fellow cites. - The 20-group limit is lifted, and no app-added 1–10 suppression applies. There is no row withholding, no "total beside its parts" rule, and no rate × population rule. Those existed only to enforce the replaced rule and are removed. - The source's own suppression is absolute. Cells the source withheld ("Suppressed", "<10", "(D)", "*", "≤10", "1–9" and similar) stay hidden and are never turned into numbers. An answer built on one (a change, a rank, a comparison) says so rather than computing. - Nothing is invented or filled in. - Patient-level data keeps every rule. Only a declared table that detection confirms as public estimates, with no patient-like structure (above), is treated this way. - Undeclared estimate tables. Statistic questions are refused, because each row would be one person and a small cell: "…It wasn't marked 'Public population estimates – no patient-level data' at upload… upload it again with that box ticked." Hospital extracts keep the full rules, and detection alone never relaxes anything. - UI. The upload checkbox in Electron is the next PR. The API and the harness carry the mark now.

    8. Packed cells, interval columns, source markers and years as columns (storage/staging.py)

    • Source markers. In a declared public table or a CDC WONDER-shaped file only (7, fail closed), a column whose other cells are all numbers keeps its numbers when the source writes "Suppressed" (CDC WONDER, 1–9 deaths), "12.3 (Unreliable)" or "Not Applicable". A suppressed cell becomes empty with <column> suppressed true; an unreliable value keeps its number with <column> unreliable true. Answers name both; a suppressed cell is never read as 0.

    • Interval columns. A column named for an interval (95% CI (%)) whose every cell is "lo to hi" becomes <column> lower and <column> upper, paired with the one estimate column (FluVaxView).

    • Packed cells. A text column whose every non-empty cell is "v (lo, hi)" becomes x, x lower and x upper. These pair as bounds (1).

    • Years as columns. Three or more packed columns whose headers each name one year ("Mortality Rate, 1980*") are unpivoted to year plus the value columns, before typing.
    • Everything else. Other columns are untouched.

    9. Fit with steps 3–4 of the steel thread

    • Step 3 (contract as context). The contract now carries privacyClass: public_aggregate. Next: the estimate key, aliases, attributes, totals and bounds as customProperties on the table object (grain: estimate, keyColumns, totalLevels, boundsOf), rendered into the model's context (#107), so the model sees "one row per location × year × sex; Both is the total" and stops writing pooled plans.
    • Step 4 (governed SQL).
    • contracts/gate.py reuses check_plan's rules on the SQL AST. An aggregate over a value column with an open key dimension is refused (§5.2 "Pooling rates"). A WHERE that keeps a total beside its parts is rewritten or held (§5.2 "Overlapping categories").
    • The privacy rewrite of §4 is skipped only for public_aggregate tables, and only for non-count value columns.
    • Order. Both steps read the same detection result, so intent and SQL answers agree.

    10. Joining public tables (core/estimate_join.py, POST /api/aggregate/questions)

    A fellow uploads the tables a paper needs, each declared, and asks across them. The route takes dataset_ids, the question and confirmed choices; it answers, holds (with options) or refuses. Deterministic: no model runs on this path.

    • Stages. Each upload's active version is read once (typed Parquet) → detected (§1) → pinned → harmonized → grain-checked → joined → answered. Rows left out at each stage are counted and named.
    • Pinning. Every key dimension that is not a join role (cause, measure, metric, rei, ICD code, indicator) must come down to one level: a choice, a level the question names (with ID abbreviations such as HCV, HIV, LRI expanded), a hold offering the total, or a refusal listing the levels. One-value columns are named in the method ("measure_name = Deaths").
    • Join roles and keys. State (name, USPS code, FIPS number or NN000 all become the two-digit FIPS text, contracts/geography.py), year, sex (Female, Male, Both) and, only when asked "by age", age. GBD's location_id is never read as FIPS. The nation is a total and is never ranked among states. Counties, cities and local jurisdictions are never joined at state grain: a county table (PLACES, SVI) is refused with that reason, never rolled up. Rows with an empty key (WONDER's "Total" rows) are left out and counted.
    • Grain. After pinning, each table must have one row per harmonized key (GX expect_compound_columns_to_be_unique), or nothing is answered. A key the joined rows vary on that a table lacks (a table with no year beside a trend) is refused, never repeated beside each level.
    • Time. A table without the asked year is held with its nearest earlier year offered ("show PLACES 2022 beside 2023"); a flu-season table is held with the season ending in that year, and is refused over a range of years. The answer names the year used for each table.
    • Measures. Values compared across tables (the disagreement screen) must be the same kind (rate, count, percent), on the same scale, and the same standardization: age-standardized is never compared with crude, and two age-standardized rates only with the same known standard population (GBD's world standard is not CDC's 2000 US standard). A rate that doesn't say which it is is held for the person to confirm. Side-by-side tables need none of this, because nothing is computed across them.
    • Analyses. table (side by side); change (each year with its own interval; change and percent change; never an interval for the change from the years' intervals, and "the intervals overlap" never called "no change"); rank (point rank and the range of ranks the intervals allow); disagree (a reported value above, below or inside a modelled interval; a screen, not a test); precision (relative interval width, widest first). "Average … from 2010 to 2023" shows the years and says no average is computed.
    • Privacy (trust the source, §7). Every table must be declared for its current version (refused otherwise, before any of its levels is named). Published values are shown as published. A cell the source suppressed is never a number: a change, rank or disagreement built on one is not computed, and the answer says the source suppressed it. Summary ages (All ages, Age-standardized) are not groups of a breakdown by age.
    • Places and standardization.
    • In a table that also lists foreign countries, "Georgia" is ambiguous and is left out, named. US territories (PR, GU, VI, AS, MP) are territories, not countries, so they don't make it ambiguous.
    • Whole state names are read before regions, so "South Carolina" never names the South.
    • Counties nest under their own state (by FIPS alias or a ", CO" suffix), so "Which Colorado county…" ranks Colorado's counties only.
    • A "crude" or "age-standardized" phrase followed by "for/in/from " belongs to that table ("age-adjusted for WONDER, crude for GBD"); otherwise it belongs to the nearest table name. A named table with no phrase of its own gets none.
    • A metric's kind is read from the named metric (metric_name), never from a code beside it (metric_id). A "%" level is a percent. "Age-adjusted Death Rate" is a rate.
    • Detroit and out-Wayne. A question about Wayne County on a table whose Wayne rows are out-Wayne (Wayne County excluding Detroit) is refused on both paths, saying why and that a whole-county count is Detroit plus out-Wayne (counts only). Detroit and out-Wayne are never treated as totals of the counties beside them.
    • Confirmed choices are saved per dataset version (DimensionChoice), so a confirmed question is not held twice; a choice that names no column or published level is rejected (400).

      • Joins (round 7). - Two monthly tables set to the same month answer disagreement and change questions: a change compares that month of each year asked. The month-versus-year note appears only beside an annual table. - "Unknown" and "Other" rows left out of a state comparison are named in the note. - estimate/estimate_low/estimate_high pair as an interval.

      Joins (round 6). - A month named against an annual table is answered side by side with a note saying one value is for one month and the other for the whole year. A disagreement or change between them is refused. Two monthly tables set to different months are never joined as one year. - A file's only year (a one-value year column) can be confirmed beside another year; the confirmation is accepted, never rejected with 400. - A table with no time at all is not an annual partner, so a monthly table beside it isn't held. - Lab reference ranges ("Result Low"/"Result High") are not intervals; only CI, confidence, limit or bound names and lower/upper pairs are. - Total rows are never listed among the territories, regions and countries left out.

      Intervals and joins (round 5). - Interval columns pair with their value by name: "Lower 95% CI"/"Upper 95% CI" beside one rate, " Lower 95% Confidence Interval" (WONDER), lci/uci, <value>_lower/_upper. They are never offered as values. The disagreement screen uses both intervals and shows them. - A year-aligned season table with a one-value year column joins without a duplicate key. - "respectively" binds only when it closes a list of phrases right after a list of the tables; years, places or other words in between, or an explicit "for WONDER", stop it. - "By month from 2019 to 2023" keeps every year in the range. - A monthly table beside an annual one is held for one month; "all months" is not offered (each annual value would repeat), and no annual sum or mean is computed from months. - Freely associated states (Palau, the Marshall Islands, Micronesia) are territories, so one of them never makes "Georgia" a country. Territories, regions and countries are left out of a state join with a note naming them. - A declared estimate table is never asked "Is each row one patient?".

      Monthly tables and county rankings (round 4). - A key of YYYY-MM levels is a month dimension, never a flu season. "Rate in 2023" on a monthly table is held with the choices "all months" (each month of 2023 shown) or one month; it never picks a month silently. A named month ("2023-03") is used as asked; a ranking needs one month. - "GBD and WONDER, age-standardized and crude respectively" binds tables in the order named to phrases in the order written; if the counts differ, nothing is bound and the choice is held. - "Which Texas county ..." on a file of several states' counties ranks Texas's counties only when every county's state is known (county FIPS or "County, ST"). Otherwise it is refused, never a partial ranking or one mixing states.

      11. Follow-ups (not in this change)

      • Electron: the upload checkbox (sending the exact form value) and a picker for joined questions.
      • Sum disjoint count levels (WONDER B17.1 + B18.2 for HCV deaths; Detroit + out-Wayne), refusing a sum that includes a cell the source suppressed.
      • Published GBD change files (year_start/year_end with their own intervals): read the change and its interval instead of only the yearly values.
      • County rollups for counts, with populations; state-based SVI.
      • Ecological correlation across states (for example PAF against smoking prevalence), with its limits stated.
      • Route the chat path's declared-estimate questions through this engine, so one question gets one answer whichever path it takes.

      Consequences

      • Correct answers or correct holds replace pooled answers on population files. On the three single-table CDC sets in the corpus, with no model: 0 WRONG and 0 LEAK (the PR records the table). The six paper ideas of the ID-fellow guide run end to end on synthetic GBD-shaped tables where their data joins at state grain (tests/api/test_aggregate_papers.py).
      • Residual: counts. Count tables with stacked grains (CDC provisional COVID: by total, by year and by month in one file) are detected, and their totals are left out of groups. Summing counts across rows is not offered.
      • Residual: long format. Long-format files that put a value and its bounds in separate rows (CMS HAI HAI_6_SIR/_CILOWER) are not detected yet. They need a pivot by measure and are answered under the full rules.
      • Residual: weights. No weighted pooling until a weight column is declared.
